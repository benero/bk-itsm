# 附件下载路径与工单归属保护

保留原 open/v3 配置位置及 NFS、BKRepo、Ceph 后端，不移动存量文件。

## 文件系统下载边界

文件系统下载按 SYS_FILE_PATH 构造受限读取对象。该配置必须为非空、非 `/` 的绝对附件目录。目录内历史绝对路径和相对路径继续支持。

逐级目录描述符和 O_NOFOLLOW 拒绝目录外路径、父目录段、根内符号链接及非普通文件，检查后替换链接也无法绕过。配置的挂载根本身可以是链接，根内链接均拒绝。misc 下载打开与检查相同的文件。

## 新上传附件的工单归属

新增 `attachment_attachment` 表，记录服务端附件 ID、存储路径、上传人和所属工单。新文件名包含 `__itsm_attachment_<随机ID>`，前端仍使用原有 name/path 响应，无需修改。只靠修改 JSON key、编码路径或删除记录，不能将新附件降级为历史文件。

- 创建工单、普通节点提交、会签和公共字段修改时，仅上传人可绑定未归属附件；已归属当前工单允许其他合法处理人再次提交，禁止改绑其他工单。
- 归属绑定与字段写入使用事务；批量绑定失败整体回滚。会签在处理结果写入及完成标记之前检查并绑定。
- 代提单使用实际登录上传人的身份绑定，而非被代提的 creator。创建接口在返回成功前完成绑定；通知和异步启动在数据库事务提交后执行。提交后启动失败保留工单及附件归属，不自动删除工单或解除归属。
- 自动化触发器不能认领用户的待绑定附件；允许保留当前工单已绑定的附件和历史值。
- 下载先保留原有资源权限检查，再验证附件所属工单。模板、版本及 misc 下载不能读取其他工单的已绑定附件。
- 附件从字段中移除不解除归属，删除工单也不清空归属；避免文件再次成为可认领的待绑定附件。

本次保护提交到工单的附件，未绑定的流程模板仍沿用原模板权限，不实现完整的模板归属与共享模型。独立任务模块的附件生命周期不在本次范围内。

## 历史与部署

历史工单/附件不回填、不迁移。旧文件名未携带新标识时沿用已有访问行为，因此历史附件的目录内跨资源归属问题未在本次解决。旧工单中新上传并提交的附件按新规则绑定。

上线先执行常规数据库迁移，创建新表，再更新所有应用与异步 worker。新文件标识若查不到记录会拒绝访问；不要删除归属记录或单独回退下载校验。上传成功但数据库登记失败可能留下无法下载的孤立文件，本次不增加自动清理任务。
